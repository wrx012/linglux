# Security Policy

## Reporting a Vulnerability

Do not report security vulnerabilities, exposed credentials, private media, personal data, or exploitable path-handling details in a public Issue.

Use [GitHub Private Vulnerability Reporting](https://github.com/wrx012/linglux/security/advisories/new) to report a vulnerability privately. Include the affected version or commit, impact, reproduction details, and a minimal sanitized proof of concept when it is safe to do so.

If private reporting is temporarily unavailable, do not open a public Issue containing sensitive details. Contact a repository administrator and ask them to enable Private Vulnerability Reporting before sharing the report.

## Scope

Security reports may cover the desktop application, Tauri permissions and commands, credential storage, provider communication, managed media paths, project persistence, FFmpeg execution, local task handling, and dependency or build configuration.

General defects without a security impact should use the Bug report form instead.
